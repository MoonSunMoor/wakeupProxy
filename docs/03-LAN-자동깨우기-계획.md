# LAN 자동 깨우기 계획

작성일: 2026-11-24 · 상태: v1 이후 검토 항목

v1 이후 LAN 기기에서도 연결하면 자동으로 깨우게 하는 계획이다. 지금 LAN 기기는 타깃과 직접 통신해 홈서버를 거치지 않으므로, 별칭 IP로 홈서버를 거치게 한다. 이름 해석(DNS)은 쓰지 않는다. 기본 동작은 [기능 명세](01-기능명세.md)를 따른다.

## 구성

- 공유기에 정적 라우트를 넣는다: 별칭 대역 → 홈서버 LAN IP.
- LAN 인터페이스를 유입 인터페이스에 추가한다. 기본값은 꺼짐인 선택 기능이다.
- LAN 유입에서는 별칭 목적지만 가로채고, 실제 IP 목적지는 가로채지 않는다.
- 허용은 LAN 대역 전체가 아니라 DHCP 예약으로 고정한 기기 IP 단위로 클라이언트에 등록한다.
- 자동으로 깨울 타깃마다 별칭을 붙이고, LAN 기기는 그 별칭 IP로 접속한다. 실제 IP로 접속하면 지금처럼 직접 통신하고 깨우지 않는다.
- 데몬 변경: 유입 인터페이스별 "별칭만 가로채기" 옵션.

## 고려할 점

- 보안: LAN에서 출발지 IP는 기기를 구분할 뿐 인증이 아니다. 다만 LAN 기기는 지금도 깨어 있는 타깃에 직접 접속하고 매직 패킷도 직접 보낼 수 있어, 늘어나는 위험은 작다. 타깃의 RDP·SSH 인증은 그대로다.
- 비대칭 경로: 요청은 공유기를 거쳐 홈서버로 가고 응답은 LAN으로 바로 간다. 상태 추적 방화벽이 있는 공유기에서는 끊길 수 있어 확인이 필요하다. DHCP 옵션 121로 별칭 대역 경로를 기기에 직접 내려 주면 해소된다.
- 별칭으로는 프로파일에 등록된 TCP 포트만 동작한다. SMB 등 나머지는 실제 IP로 접속한다.
- 홈서버(A53)를 거치므로 LAN 직접 통신보다 느려질 수 있고, 홈서버가 죽으면 별칭 경로도 끊긴다(실제 IP 직접 접속은 가능).
- 공유기가 정적 라우트를 지원해야 한다. 통신사 기본 공유기는 지원하지 않는 경우가 많다.
